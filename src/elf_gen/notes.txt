My goal is to build an elf analyzer
that takes the raw elf and then generates a representation of the virtual memory range for loadable data
the code segment is what I really care about, and that is what can grow in size after performing the 
translation.

We only care about loadable segments, for now
I think the elf decoder already has support for figuring out the range, I just need to understand the meaning of certain segment properties again.

offset: where segment bytes start in the ELF file
filesz: how many bytes of segment data exist in the ELF file
vaddr: virtual address where segment is loaded
memsz: total in-memory size of the segment after loading, including zero-filled bytes

if I recall correctly, there was also some condition between offset and vaddr?
vaddr % p_align == offset % p_align
I feel page alignment should be inheritted from the original elf
